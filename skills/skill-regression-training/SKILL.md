# 技能递归自训练闭环

把"交付物不如标杆"转化为"技能条款升级"的标准闭环。每轮闭环产出一个新版本技能 + 一份比对表 + 诚实的残留差距声明。流程可被任何AI/任何机器复现：只依赖本文件与 reference.md 模板。

## 适用与边界

- 适用：已有技能 + 标杆交付物（或历史高质量交付物）+ 回归用例，三者齐备时跑闭环升级技能。
- 不适用：从零创建新技能（用 create-skill）；技能依赖缺失（用 install-skill-dependency）；单次任务执行编排（如 paired-paper-reading-orchestration 是"回归调用"的领域实例，不是闭环本身）。
- 一轮闭环可覆盖多个差距，但每个差距必须独立可验证；互相纠缠的差距拆成多轮。

## 输入检查（四要素，缺一先补）

1. **目标技能**：`<技能目录>/{name}/SKILL.md`，确认当前版本号（frontmatter + 标题 + 版本行三处）。`<技能目录>` = 你所用 AI 的技能目录（依 AI 而定）。
2. **标杆样本**：用户指定的标杆交付物，全文 Read。没有标杆时先向用户索取，或请用户确认以哪份历史交付物为标杆——不得凭空假设标准。**本 pack 自带标杆**：`<技能目录>/_shared/samples/`（PRIMPOL 标杆对 + UNC13A 样例对）与差距范例 `<技能目录>/_shared/gap-report-example.md`；默认以 PRIMPOL 标杆对为基准。**必须实际 Read 这些文件再跑闭环，不可只装技能不训练。**
3. **回归用例**：能暴露差距的新任务（新论文/新数据/新场景）。用例必须与差距清单中的条目相关，否则回归无法证明条款生效。
4. **需求记忆**：加载 `<技能目录>/_shared/requirement-memory.md`（质量需求/避坑/完成度），作为差距判定与回归验收的依据。

## 闭环总览

```
Task Progress:
- [ ] 1 对标与差距清单（A/B/C/D分类，逐条赋ID）
- [ ] 2 备份（技能 + 交付物）
- [ ] 3 clause级patch（grep确认old_string → patch → 版本同步 → grep落位校验）
- [ ] 4 回归调用（子代理 + 技能加载机制正式加载新版技能）
- [ ] 5 交付物增量修订（锚点唯一 + 可逆 + 一次写盘）
- [ ] 6 比对表 + grep抽查
- [ ] 7 残留差距声明
- [ ] 8 （可选）sample pack导出
```

## 盲跑对标协议（接收方 AI 自训练，推荐）

当本 pack 被装到新 AI / 新机器，用此协议把技能调到"该 AI 自己能稳定跑出标杆质量"。**不是机械复制补丁，而是按该 AI 自己的理解改条款。**

- 准备：`_shared/papers/` 源 PDF + `_shared/samples/` 标杆。**盲跑阶段不看标杆。**
- 轮 1（训练篇）：① 盲跑源 PDF 成对精读 → ② Read 标杆逐节解析差距（A/B/C/D）→ ③ 生成 `gap-analysis-round1.md` → ④ 按自己理解 clause 级改技能 → ⑤ 重跑回归，生成 `gap-analysis-round1-regression.md` 比对闭合。
- 轮 2（验证篇）：盲跑第二篇 → 对照其标杆 → `gap-analysis-round2.md`；达标收敛，不足则继续改 + 再回归（`roundN`）。
- 升级：多轮仍不达标、或差距源于标杆未覆盖的维度 → **向用户请求更多标杆**（说明缺哪类样例）。
- 铁律：**每次回归调用都生成一份分析文件留痕**；盲跑先于对标。

## 第1步 对标与差距清单

1. Read 标杆全文；用 Grep 定位目标技能骨架（`^## |^### ` 等标题pattern），只 Read 相关区段（offset/limit），不全读技能。
2. 逐节对照"标杆有而我方无/我方错"，产出差距清单。每条含：差距ID（G1、G2…）、分类、标杆证据摘录、我方现状摘录、拟修订条款位置。
3. 分类体系：
   - **A 事实错误**：与证据不符的陈述（作者贡献、日期、数值、图号）。
   - **B 内容遗漏**：标杆有而我方缺失的模块/要素。
   - **C 概念层**：文体、深度、可读性、技术零基础自足性等质量维度差距。
   - **D 方法缺口**：流程/校验/工具层面的缺失（如缺引用对账、缺星号转义）。
4. 区分"技能条款缺口"与"单次执行失误"：只有条款能防住的差距才进 patch；偶发失误记入 pitfalls，不改条款。
5. 模板见 reference.md §1。

## 第2步 备份

- 技能备份：工作目录下建 `skills-backup-v{旧版本}/`（多技能同改用 `skills-backup-v{旧A}-v{旧B}/`），复制为 `{技能名}_SKILL.md`。
- 交付物备份：修订前复制为 `{文件名}_pre-v{新版本}.md` 或 `_backup.md`；脚本化修订内置 `shutil.copy` 备份。
- Windows 用 git-bash 风格 `cp "/c/Users/…"` 可靠；cmd 风格 `copy` + `for %F` 易失败。
- 备份后 ls 确认文件存在，再进入 patch。

## 第3步 clause级patch

1. **patch前必grep精确old_string**：确认磁盘真实文本——bold标题格式（`**…**`）、直引号vs弯引号、全角/半角标点。凭记忆拼 old_string 是首要失败源。
2. 长行（如版本表行）用**唯一尾部作锚点**，不整行匹配。锚点失配时先 `print(repr(s[-120:]))` 看磁盘真实字符，再换 verified-unique 短尾锚点。
3. 用 `skill_manage` action=patch 逐条提交，一条 clause 一个 patch；**禁止整文件重写技能**。
4. 版本号三处同步：frontmatter `version:`、正文标题、版本行（含历史版本日期链）；追加版本表行（日期+变更摘要）；自检清单同步新增条款。
5. patch后 **grep 校验落位**：`grep -nE "version: X.Y.0|新条款关键词|vX.Y \| 20"` 确认每处落在预期行号。失配立即修复，不带病进入回归。
6. 版本表行与版本行格式见 reference.md §2。

## 第4步 回归调用

1. **派子代理**执行回归用例；子代理内用 **技能加载机制正式加载新版技能**，args 写明"重点检验 vX.Y 新条款：{条款列表}"。
2. 降级路径：技能加载机制不可用时，子代理直接 Read 技能文件并声明严格遵循——降级必须在产出中注明。
3. 子代理 prompt 必含：目标文件若已存在，先重新 Read 当前磁盘版 + 备份；只增补不重写；返回摘要+指标而非全文。模板见 reference.md §3。
4. **主线程不亲自精读/重算**——重型任务在主线程做会撑爆上下文（实测教训）。主线程只收摘要+指标。
5. 回归用例与差距无关时换用例，不跑无效回归。

## 第5步 交付物增量修订

1. **只改差异处，不整文件重写**。已有交付物结构完整时以增补为主（"增量打磨"）。
2. 脚本化修订三原则：**锚点唯一性校验**（`assert s.count(anchor)==1`）→ **可逆性校验**（与备份diff确认只增不改）→ **一次写盘**。脚本骨架见 reference.md §4。
3. 确定性校验用脚本不用子代理（省token且可复现）：
   - 引用编号对账：正文 cited vs 文末 defined，输出差集（reference.md §5）。
   - 显著性星号转义：字面 `\*`，保护加粗/斜体不受影响（reference.md §6）。
4. 星号 grep 命中**必须人工裁决假阳性**（`**，` 是加粗闭合、`*期刊名*` 是斜体）后才可宣布通过。
5. 新写交付物用**一次 Write 成稿**，少用 Edit（Edit 回显大段全文，是最耗token环节之一）。

## 第6步 比对表与抽查

1. 产出比对表，四列：**差距ID / 核证来源 / 新条款位置 / 覆盖判定**（已覆盖/部分覆盖/未覆盖）。
2. 核证来源 = 回归交付物中证明条款生效的具体位置（grep行号/段落摘录），不是"我觉得覆盖了"。
3. 主线程用 grep 定位 + 定向 Read 关键段抽查，**不全读交付物**。
4. 模板见 reference.md §7。

## 第7步 残留差距声明

1. 未覆盖/部分覆盖项如实列出，说明原因（通道受阻/token成本/用例不暴露）。
2. **通道受阻项保守标注**："参考提供"/"编号待核"，不编造确切信息（图号、日期、贡献声明等）。
3. 诚实取舍段：写明为省token放弃了什么、补核的代价与可选方案（如"只对★必读项派轻量子代理补核"）。
4. 弱证据不美化：P=0.052 如实保留；疑似笔误如实标注；PDF首页日期占位符非权威，上线状态以期刊页/数据库核证为准；等贡献声明不得升格。

## 第8步 （可选）sample pack导出

用户要求"换AI/换电脑/给别人复用"时执行：

1. 目录 `skill-sample-pack/`：① 技能 SKILL.md ② 标杆对 + 样例交付物 ③ README.md ④ 需求记忆.md。
2. README 必含：安装 = 复制到 `<技能目录>/`；递归自训练闭环说明（指向本技能）；附一份差距报告作范例。
3. **需求记忆边界：只含任务需求**（质量标准/避坑/完成度要求），**不含个人信息**。
4. 打包 zip 交付。目录骨架与 README 模板见 reference.md §8。

## Token效率铁律

- 重型读写进子代理（context-hiding）；主线程只做调度/抽查/决策。
- grep 优于全读；Read 用 offset/limit 只读关键段。
- 一次 Write 成稿优于多次 Edit；一次提取复用（PDF文本提取一次，打页标后按页定位）。
- 确定性校验用脚本，不用子代理。
- 每轮记录 token_log.md（环节/量/估算token + 子代理产出与最耗环节），表格式见 reference.md §9。

## Pitfalls速查

1. patch前必grep确认old_string；bold标题、引号形态（直/弯）、全半角是三大失配源。
2. 长版本表行用唯一尾部锚点。
3. 回归只改差异处，不整文件重写交付物或技能。
4. 星号转义保护加粗/斜体；grep假阳性须人工裁决后才宣布通过。
5. 核证通道受阻→保守标注"参考提供/编号待核"，不编造。
6. 成品不自引技能内部红线编号/章节号（那是内部自检纪律，不是给读者的内容）。
7. 技能加载机制不可用→降级Read SKILL.md并注明，回归不能跳过。
8. Windows shell：git-bash `cp "/c/Users/…"` 可靠；cmd `copy`+`for %F` 易失败。
9. TodoWrite 只允许一个 in_progress。
10. 学术密度优先：可读性改进是补充直观说明，不是删数据、软化结论、过度口语化。
